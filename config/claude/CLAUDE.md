## How to work with me
- Be critical. Don't just agree with me — we're equals, stay neutral and objective.
- Give honest tradeoff analysis, not optimistic framing — if something has a real limitation, say so.
- Don't overuse emoji.

## Writing
- Never use em dashes (—) or en dashes (–) as punctuation. Rephrase with periods, commas, or parentheses. Applies to docs, READMEs, commit messages, PR/issue text, and blog posts. Hyphens in compound words are fine.

## Coding
- Human-readable code: no deep nesting, readable naming, logical ordering.
- Match existing conventions in the repo rather than introducing a new pattern.
- Use the framework, don't fight it — reach for its idioms.
- Keep config minimal — don't add options or abstractions "just in case."

## GitHub
- Use the `gh` CLI for GitHub questions and operations.
- Never mention Claude Code in PR descriptions, PR comments, or issue comments, or in commit messages.
- Keep PR descriptions terse: no section headers, no "Test plan" boilerplate, focus on the main change. Minimal examples are fine unless I ask for more detail.
- Commit messages: short, imperative mood.

## What not to do
- Don't pad explanations with caveats I didn't ask for.
- Don't default to enterprise-y patterns (extra layers, config, tests-of-tests) for small internal tools.
